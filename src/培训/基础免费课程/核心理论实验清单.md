### 实验 1：`<script>` 的 defer vs async vs 普通脚本

**🎯 问题**：脚本放 `<head>` 里为什么会阻塞页面？defer 和 async 到底差在哪？

**📝 实验代码**：

创建三个文件，分别运行观察。

> **1. 普通脚本（阻塞）**
```html
<!DOCTYPE html>
<html>
<head>
  <title>普通脚本</title>
  <script>
    console.log('普通脚本执行');
    console.log('此时 body 是否存在：', document.body);
  </script>
</head>
<body>
  <p>页面内容</p>
  <script>
    console.log('body 内脚本执行');
  </script>
</body>
</html>
```

> **2. defer 脚本**
```html
<!DOCTYPE html>
<html>
<head>
  <title>defer 脚本</title>
  <script defer src="test.js"></script>
  <!-- test.js 内容：console.log('defer 执行，body=', document.body); -->
</head>
<body>
  <p>页面内容</p>
</body>
</html>
```

> **3. async 脚本**
```html
<!DOCTYPE html>
<html>
<head>
  <title>async 脚本</title>
  <script async src="test1.js"></script>
  <script async src="test2.js"></script>
  <!-- 两个文件分别 console.log 自己的文件名 -->
</head>
<body>
  <p>页面内容</p>
</body>
</html>
```

**🔍 观察点**：
- F12 → Console 面板：看日志输出顺序
- F12 → Network 面板：看请求是否并行
- F12 → Performance 面板（进阶）：录制页面加载过程，看脚本执行时机

**✅ 预期现象**：
| 类型 | document.body | 执行顺序 | DOMContentLoaded 关系 |
|------|--------------|----------|----------------------|
| 普通脚本（head）| `null` | 立即执行 | 阻塞触发 |
| defer | 有值（已解析）| 按出现顺序 | 在此之前执行 |
| async | 不一定 | 下载完谁先好谁先执行 | 不确定 |

**🎯 问题**：不写 `<!DOCTYPE html>` 会怎样？

### 实验 4：盒模型 box-sizing

**🎯 问题**：`width: 100px` 到底指哪部分的宽度？

**📝 实验代码**：
```html
<!DOCTYPE html>
<html>
```

- `content-box` 总宽 = 100 + 40 + 10 = **150px**
- `border-box` 总宽 = **100px**（内容区被压缩为 100 - 40 - 10 = 50px）

### 实验 5：BFC（块级格式化上下文）

**🎯 问题**：为什么父子元素的 margin 会"塌陷"？怎么用 BFC 解决？

**📝 实验代码**：
```html
<!DOCTYPE html>
<html>
<head>
<style>
  .parent {
    background: #ccc;
    /* 尝试分别打开以下属性，观察变化 */
    /* overflow: hidden; */
    /* display: flow-root; */
  }
  .child {
    margin-top: 50px;
    width: 100px; height: 100px;
    background: red;
  }
  .sibling {
    margin-top: 30px;
    width: 100px; height: 100px;
    background: blue;
  }
</style>
</head>
<body>
  <div class="parent">
    <div class="child">子元素</div>
  </div>
  <div class="sibling">相邻元素</div>
</body>
</html>
```

**🔍 观察点**：
- 未开启 BFC 时：子元素的 `margin-top: 50px` 会"穿透"父元素，导致父元素整体下移
- 开启 `overflow: hidden` 或 `display: flow-root` 后：父元素包裹住子元素的 margin

**✅ 预期现象**：
| parent 样式 | 结果 |
|------------|------|
| 无 | 父元素和子元素一起下移，父元素上边距消失（margin 塌陷）|
| `overflow: hidden` | 父元素保持原位，子元素在父元素内部有上边距 |
| `display: flow-root` | 同上，现代推荐方案 |

### 实验 8：Flex 布局 vs Grid 布局

### 实验 9：var vs let vs const

**🎯 问题**：为什么循环里用 `var` 输出结果总是最后一个？

**📝 实验代码**：
```html
<!DOCTYPE html>
<html>
<body>
<script>
  // 实验 A：变量提升
  console.log(a); // ?
  var a = 1;
  // console.log(b); // 打开会报错吗？
  let b = 2;

  // 实验 B：作用域
  for (var i = 0; i < 3; i++) {
    setTimeout(() => console.log('var i:', i), 100);
  }
  for (let j = 0; j < 3; j++) {
    setTimeout(() => console.log('let j:', j), 100);
  }

  // 实验 C：重复声明
  var a = 100; // 会报错吗？
  // let b = 200; // 打开会报错吗？
</script>
</body>
</html>
```

**🔍 观察点**：
- `var` 的变量提升：声明会提升到作用域顶部，赋值不会
- `var` 没有块级作用域：循环中的 `i` 是全局同一个变量
- `let` 有块级作用域：每次循环 `j` 都是新的绑定
- `const`：必须初始化，不能重新赋值（但对象属性可以改）

### 实验 10：this 指向

**🎯 问题**：箭头函数的 `this` 和普通函数的 `this` 有什么区别？

**📝 实验代码**：
```html
<!DOCTYPE html>
<html>
<body>
<script>
  const obj = {
    name: 'obj',
    normalFunc: function() {
      console.log('normal:', this.name);
    },
    arrowFunc: () => {
      console.log('arrow:', this.name);
    }
  };

  obj.normalFunc(); // ?
  obj.arrowFunc();  // ?

  // 作为回调
  const btn = { name: 'btn', onclick: obj.normalFunc };
  btn.onclick(); // ?

  // setTimeout
  setTimeout(obj.normalFunc, 0); // ?
  setTimeout(() => obj.normalFunc(), 0); // ?
</script>
</body>
</html>
```

**🔍 观察点**：
- 普通函数：`this` 取决于**调用方式**（谁调用指向谁）
- 箭头函数：`this` 取决于**定义位置**的外层 `this`
- `setTimeout(fn, 0)` 相当于 `fn()`，丢失原对象绑定

### 实验 12：事件循环 Event Loop

**🎯 问题**：`setTimeout(fn, 0)` 真的是 0 毫秒后执行吗？

**📝 实验代码**：
```html
<!DOCTYPE html>
<html>
<body>
<script>
  console.log('1. 同步代码开始');

  setTimeout(() => console.log('2. 宏任务 setTimeout'), 0);

  Promise.resolve().then(() => {
    console.log('3. 微任务 Promise1');
    return Promise.resolve();
  }).then(() => {
    console.log('4. 微任务 Promise2');
  });

  console.log('5. 同步代码结束');
</script>
</body>
</html>
```

**🔍 观察点**：
- 输出顺序是什么？（正确顺序：1 → 5 → 3 → 4 → 2）
- 为什么不是 1 → 2 → 3 → 4 → 5？
- 执行顺序：**同步代码 → 微任务（Promise）→ 宏任务（setTimeout）**

### 实验 13：== vs ===

**🎯 问题**：`==` 的比较规则有多奇怪？

**📝 实验代码**：
```html
<!DOCTYPE html>
<html>
<body>
<script>
  console.log(0 == '0');      // ?
  console.log(0 == []);       // ?
  console.log('0' == []);     // ?
  console.log(null == undefined); // ?
  console.log(null === undefined); // ?
  console.log(NaN == NaN);    // ?
  console.log(Object.is(NaN, NaN)); // ?
</script>
</body>
</html>
```

**🔍 观察点**：
- `==` 会发生**类型转换**，规则复杂且容易踩坑
- `===` 严格相等：值和类型都相同才为 `true`
- 建议：除了 `null == undefined` 这种明确场景，一律使用 `===`

### 实验 14：原型与原型链

**🎯 问题**：`obj.toString()` 这个方法定义在哪里？

**📝 实验代码**：
```html
<!DOCTYPE html>
<html>
<body>
<script>
  function Person(name) { this.name = name; }
  Person.prototype.sayHi = function() { console.log('Hi, ' + this.name); };

  const p = new Person('Tom');

  console.log(p.__proto__ === Person.prototype); // ?
  console.log(Person.prototype.__proto__ === Object.prototype); // ?
  console.log(Object.prototype.__proto__); // ?
  console.log(p.toString === Object.prototype.toString); // ?

  // 遍历原型链
  let proto = p;
  while (proto) {
    console.log(proto.constructor?.name || 'null');
    proto = proto.__proto__;
  }
</script>
</body>
</html>
```

**🔍 观察点**：
- `p` 本身没有 `toString`，为什么会找到 `Object.prototype.toString`？
- 原型链的终点是 `null`
- `__proto__` 是浏览器实现的非标准属性，标准用法是 `Object.getPrototypeOf()`
