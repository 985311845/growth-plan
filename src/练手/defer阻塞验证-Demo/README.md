# defer 阻塞验证 Demo

> 解决"本地文件加载太快，无法验证 defer 阻塞行为"的痛点。

## 🎯 验证目标

证明：**多个 defer 脚本虽然并行下载，但执行是严格串行的。**

如果第二个 defer 脚本下载很慢，即使第三个已经下载完成，浏览器也会**阻塞等待第二个**，不会跳过它。

---

## 🚀 快速开始（只需 3 步）

### 第 1 步：运行服务器

确保你已安装 Node.js（前端学习必备，没装的话去 nodejs.org 下载）。

在**当前目录**打开终端，执行：

```bash
node server.js
```

看到提示就说明启动成功了：

```
============================================
🚀 服务器已启动
👉 请在浏览器打开 http://localhost:3000
🔧 打开 F12 → Network + Console 观察
🛑 按 Ctrl+C 停止服务器
============================================
```

### 第 2 步：打开浏览器观察

1. 浏览器访问 `http://localhost:3000`
2. **按 F12 打开开发者工具**
3. 切换到 **Network（网络）面板**
4. 切换到 **Console（控制台）面板**
5. **刷新页面（F5）**，观察现象

### 第 3 步：对比实验

做完上面的实验后，你可以修改 `server.js` 里的延迟时间，重新运行，观察变化：

```js
// 当前设置：A(0.5秒) → B(5秒，故意很慢) → C(0.5秒)
sendScript(res, 500,  'A');
sendScript(res, 5000, 'B');  // ← 改成 1000 试试？
sendScript(res, 500,  'C');
```

---

## 🔍 你应该看到什么？

### Network 面板（网络）

刷新后，你会看到三个请求**几乎同时发出**：

| 请求 | 状态 | 耗时 | 说明 |
|------|------|------|------|
| `a.js` | 200 | ~500ms | 很快完成 |
| `b.js` | 200 | ~5s | **故意很慢** |
| `c.js` | 200 | ~500ms | 很快完成 |

**关键观察**：三个请求是**同时开始**的，不是等前一个下完才下后一个。

### Console 面板（控制台）

你会看到类似这样的输出（时间戳会有差异）：

```
[120ms] HTML 解析完成（DOM 已就绪）
[A] 执行，时间: 620ms        ← A 先下载完，但等 HTML 解析完才执行
                              ← 这里有一段长长的空白等待期！！
[B] 执行，时间: 5120ms        ← B 等了 5 秒才执行
[C] 执行，时间: 5130ms        ← C 早就下载完了，但必须等 B 执行完才能执行
```

### ⚡ 核心现象

注意 `C` 的时间戳：

- `C` 在 **~620ms** 时就已经下载完成了（和 A 差不多时间）
- 但 `C` 直到 **~5130ms** 才执行
- 中间的 **4500ms** 左右，浏览器在**干等 B 下载完成**

这就是 **"阻塞等待"** 的证据。

## 🔄 进阶对比实验

### 实验 A：把 B 的延迟改成和 A/C 一样

修改 `server.js`：

```js
sendScript(res, 500, 'B');  // 原来是 5000，改成 500
```

重新运行 `node server.js`，刷新页面。

**预期结果**：A → B → C 几乎连续执行，中间没有明显等待。

### 实验 B：把 defer 改成 async

修改 HTML 中的 `<script defer` → `<script async`，重新刷新（不需要重启服务器）。

**预期结果**：
- A 和 C 先执行（因为它们先下载完）
- B 最后执行（不管它在文档中排第几）
- 执行顺序**不保证**是 A → B → C

## 📝 学习建议

| 误区 | 纠正 |
|------|------|
| "本地文件跑不出效果" | 用服务器模拟延迟，或用 DevTools Network Throttling |
| "改完代码没变化" | 确保**重启了服务器**（Ctrl+C 后再 `node server.js`） |
| "Console 时间戳看不懂" | 重点关注相邻两条日志的**时间差**，而不是绝对值 |

### 其他模拟延迟的方法（不需要 Node）

如果你暂时不想跑 Node，也可以这样验证：

**方法 1：DevTools Network Throttling（限速）**
1. F12 → Network 面板
2. 找到 Throttling（限速）下拉框，选择 **Slow 3G**
3. 写三个 `<script defer>`，分别引入不同大小的真实库：
   - A: jQuery（小）
   - B: Three.js（大，几 MB）
   - C: Axios（小）
4. 刷新页面，在 Network 观察大文件如何拖慢后面的执行

**方法 2：在线延迟 API（最简单但会报错）**
```html
<script defer src="https://httpbin.org/delay/1?a"></script>
<script defer src="https://httpbin.org/delay/5?b"></script>
<script defer src="https://httpbin.org/delay/1?c"></script>
```
这三个请求会分别在 1秒、5秒、1秒后返回（返回的是 JSON，会报语法错误，但 Network 面板仍能看到下载完成时间）。

## ✅ 结论填空

做完实验后，用自己的话填空：

> `defer` 脚本的下载是 ______（并行/串行）的，执行是 ______（并行/串行）的。
>
> 如果第二个 defer 脚本下载很慢，第三个脚本即使早就下载完成了，也会 ______（立刻执行/阻塞等待/跳过执行）。

（答案：并行、串行、阻塞等待）
